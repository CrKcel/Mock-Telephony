# Module Architecture

## 0. Repository Layout

- `docs/` — module documentation
- `tools/` — build/packaging/check/smoke scripts
- `module/` — KernelSU package: boot scripts, `module.prop`, `sepolicy.rule`, VINTF manifest, feature XML, supervisor/daemon self-healing
- `daemon/` — module Java sources: entry points (`MockModemMain`, `StandaloneRadioRegistrar`) and HAL runtime (`MockModemService`, `IRadio*Impl`, etc.) plus compile-only stubs
- `radio-aidl/` — frozen AIDL v1 dump + `version.properties` hash lock
- `tests/` — `contracts.sh` (module contracts + daemon contracts) and `runtime-contracts.sh`

> Files under `daemon/` and `radio-aidl/` with an AOSP header are modified from the AOSP CTS Mock Modem and the Android Radio AIDL API.  See `licenses/` for their licenses.

## 1. Responsibilities

Systemless injection of the telephony-stack Feature/VINTF, sets `ro.radio.noril=false`, and runs a static bootstrap HAL.

## 2. System-level Injection

- **Feature XML**: a uniquely named `mock-telephony-features.xml` is merged systemless into
  `/system/etc/permissions` (preserving the `android.hardware.telephony` facade).
- **VINTF**: a fragment is merged into `/system/etc/vintf/manifest`, declaring 7 AIDL radio HALs
  (`slot1`, version 1). IMS is deliberately not declared — otherwise the RIL would wait on it forever.
- **Injection backends**:
  - KernelSU/Magisk: `post-fs-data.sh` mounts its own overlay, then injects via `cp`/`chcon`;
  - APatch + overlayfs: `skip_mount` is removed at install time so APatch's native system overlay
    injects the files; `post-fs-data.sh` only captures the original property values, and
    `post-mount.sh` verifies the files and commits the properties once the manager has finished mounting;
  - kernel without overlayfs → fall back to tmpfs image + bind: copy the target directory into a private
    tmpfs, add the module files, re-label only the image root and the newly added files, then bind it back
    (`mount --bind`).
- **Properties**: `ro.radio.noril=false` is set by a shared bootstrap transaction once injection succeeds
  (post-fs-data for Magisk/KernelSU, post-mount for APatch; it is not placed in
  system.prop — otherwise the root framework loads it before the scripts, the device's original value is
  lost, and a rollback on failure becomes a no-op); at boot `persist.radio.allow_mock_modem=true` is set and
  reset to `false` on uninstall/failed rollback. The resetprop path is detected from the root framework.
- **sepolicy**: kept minimal; `sepolicy.rule` is generated by `customize.sh` at install time based on the
  detected framework — the static file ships with the KernelSU default (`ksu`/`su` domain) and is rewritten
  to the `magisk`/`su` domain at install time for Magisk/APatch, so the manager's policy compilation never
  hits a non-existent type.
- **Overlay conflict protection**: when an external module overlays the same directory as mock, the later
  executor refuses to mount rather than overwriting the other; mock's uninstall only unmounts the overlays or
  bind images it registered itself.

## 3. Static Bootstrap HAL

- On devices without a Radio HAL, `com.android.phone` waits for the default HAL before any app gets a chance to run.
- `MockModemMain` and `IRadio*Impl` register 7 services via `ServiceManager`
  (`config/default`, `modem/slot1`, `sim/slot1`, `network/slot1`, `data/slot1`, `messaging/slot1`, `voice/slot1`).
- The bootstrap is fixed to a single SIM slot, no SIM, no service (`MOCK_SIM_PROFILE_ID_DEFAULT`).

## 4. Module Java Runtime (daemon/)

`daemon/` is the module's Java component — the entry points (`MockModemMain`/`StandaloneRadioRegistrar`),
the HAL runtime (`MockModemService`/`IRadio*Impl`), and the compile-only stubs all live in one tree. The
`IRadio*Impl` classes are what `com.android.phone` talks to through the 7 registered services (see §3).
The compile-only stubs let the tree compile against the AIDL classes before the generated sources exist;
`tools/build.sh` produces `out/artifacts/mockmodem.jar` from it (see build-and-release.md).

## 5. AIDL Locking (radio-aidl/)

`radio-aidl/` is the repository's frozen dump of the AOSP Radio AIDL v1.
`radio-aidl/api/1` is the AOSP `android-13.0.0_r1` Radio stable AIDL v1 dump;
`version.properties` holds the hash of each package. Hashes follow the `latest-version` rule of AOSP's
`hash_gen.sh` and are recomputed per package at build time. The frozen dump cannot be edited directly — the
hash lock prevents drift.

## 6. Process Self-healing

- daemon supervisor: PID identity checks, backoff restarts, private
  logs; on startup the supervisor registers its own PID and, for an already-alive daemon, adopt-or-start
  (adopting via the pidfile when the daemon is not its child, to avoid a second daemon racing for the
  same-named HAL).
- Self-healing: supervisor→daemon. A crashed daemon is pulled back up by the supervisor with backoff;
- `uninstall.sh` writes a `.uninstalling` marker to prevent revival during uninstall and runs
  `set-modem-service` to restore `default`.

## 7. Install Prechecks & Uninstall

- `customize.sh`: validates the minimum Android API level (API 33+), `/system/etc/permissions`,
  and the VINTF manifest; generates `sepolicy.rule` based on the detected root framework; detects whether
  the device already has a telephony stack enabled and cancels the install (except when upgrading an
  already installed module). On install failure, the manager's `abort` cleans up `modules_update` so a
  failed package never takes effect on the next boot.
- Uninstall: restores the original property values, unmounts its own overlays, and runs
  `set-modem-service` to restore `default`.

## 8. Verification Scope & Unverified Gaps

- Full regression verification has only been done on Android 16 with KernelSU; no on-device regression on
  Magisk/APatch yet. The daemon's SELinux domain matching ( `magisk` on Magisk; APatch relies on the
  KernelPatch hook) still needs real-device testing.
